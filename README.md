# Посылка

Личный трекер одного заказа Wildberries: GitHub Pages PWA для iPhone, Cloudflare Worker с опросом каждые 15 минут, Web Push и журнал в Google Таблице. Компьютер и Codex после настройки не нужны.

## Что настроено

Адрес Worker: https://parcel-status.parcel-status.workers.dev

Публикуется только `public/`. Данные заказа выдаются защищённым API. Bearer-токен WB, идентификатор доставки и ключи хранятся отдельно от GitHub. Рабочих данных и токенов в репозитории нет. Параметр `?demo=1` включает явно помеченную демонстрацию.

## Локальная проверка

Node.js 22.12+ и npm 11.17.0:

```sh
npm ci --ignore-scripts
npm test
npm run check
npm run dev
```

Открыть http://127.0.0.1:8787/?demo=1. Без секретов API закрыт. Установочные скрипты зависимостей отключены в `.npmrc`.

## Cloudflare

После `wrangler login` опубликовать `npm run deploy`. SQLite Durable Object создаётся миграцией в `wrangler.jsonc`. Cron проверяет заказ каждые 15 минут. В настройках Worker добавить секреты:

| Секрет | Назначение |
|---|---|
| `WB_TOKEN` | Новый access token без слова Bearer. Не ID token и не cookie. |
| `WB_RID` | Идентификатор из пути `/api/v6/statuses/<RID>`. |
| `API_KEY` | Случайный ключ трекера, минимум 32 символа. |
| `VAPID_PUBLIC_KEY` | Открытая часть ключа Web Push. |
| `VAPID_PRIVATE_KEY` | Закрытая часть ключа Web Push. |
| `SHEETS_WEBHOOK_SECRET` | Отдельный ключ только для журнала. |
| `SHEETS_WEBHOOK_URL` | Адрес развёрнутого Apps Script, необязательно до подключения таблицы. |
| `SHEET_URL` | Ссылка на Google Таблицу для кнопки в приложении. |

`node tools/generate-keys.mjs` один раз создаёт исключённый из Git файл `.env.generated`. Не отправлять его в чат или репозиторий. `node tools/publish-secrets.mjs` загружает сгенерированные ключи в Cloudflare без печати значений. Не запускать генератор повторно: замена VAPID потребует переподписать устройства.

В `wrangler.jsonc` задать свой `APP_ORIGIN`, `APP_URL`, `VAPID_SUBJECT`. Ссылку `SHEET_URL` хранить как секрет Worker, чтобы не публиковать идентификатор таблицы в репозитории. Ключ WB не передаётся браузеру и не вводится в настройки PWA. Когда он истечёт, приложение покажет ошибку; автоматического обновления токена нет.

## Google Таблица

1. В существующей таблице открыть Расширения → Apps Script и вставить `google/Code.gs`.
2. В Script Properties установить `SPREADSHEET_ID` существующей таблицы и `WEBHOOK_SECRET` с тем же значением, что `SHEETS_WEBHOOK_SECRET` на Worker.
3. Запустить `setup`, согласовать доступ к своей таблице. Скрипт создаёт отдельный лист «Облако», не изменяя прежнюю историю.
4. Развернуть как web app, выполнение от своего имени, доступ для внешних запросов. URL сохранить в секрете `SHEETS_WEBHOOK_URL` на Worker. Секретный ключ обязателен в теле каждого запроса; адрес не является авторизацией.
5. Добавить секрет `SHEET_URL` с адресом таблицы.

Запись идемпотентна по точному ключу события, ошибки оставляют очередь для повтора. Адреса, код получения, данные оплаты и токен WB в таблицу не попадают. Во время перерыва связи сохраняется до 100 событий для передачи, чего достаточно для обычного одиночного заказа; при большем количестве требуется увеличить очередь.

## GitHub Pages и iPhone

Settings → Pages → Source: GitHub Actions. Workflow проверяет тесты, аудит и сборку, затем публикует `public/`. В PWA открыть настройки и ввести адрес Worker плюс отдельный `API_KEY`. Приложение хранит ключ и адрес в localStorage этого устройства. Ключ удаляется кнопкой «Выйти из трекера» или при очистке данных сайта; приватный режим не подходит для постоянного входа. В Safari и приложении с экрана «Домой» может потребоваться отдельное подключение. Разные сайты одного GitHub Pages origin разделяют это хранилище: размещать только доверенный код в других проектах того же origin.

На iPhone с iOS 16.4+: Safari → Поделиться → На экран «Домой». Открыть с иконки, подключить трекер, нажать «Включить уведомления», затем «Тестовое уведомление». Разрешение выдаётся только действием пользователя.

## API

Все `/api/*` требуют `Authorization: Bearer <API_KEY>`. Разрешён origin сайта из конфигурации. Неудачные входы ограничены 10 попытками за 15 минут на источник. Ответы не кешируются.

- `GET /api/state` — очищенная история, ошибки, открытый VAPID-ключ.
- `POST /api/poll` — ручная проверка, не чаще минуты.
- `POST /api/subscription` — JSON push-подписки, до 5 устройств.
- `DELETE /api/subscription` — удалить свою подписку (тот же JSON).
- `POST /api/test-push` — тест на подключённые устройства, не чаще минуты.

Первое чтение истории не создаёт push. Дальнейшие новые события сравниваются по статусу и исходным наносекундам. Сбой не затирает последний статус. При окончательном событии проверки останавливаются. Apple/Google/Mozilla push-endpoints разрешены явно, перенаправления при отправке запрещены.

Web Push — доставка с повтором. При падении между отправкой и сохранением подтверждения возможно повторное уведомление; одинаковые теги объединяются устройством. Временный сбой отображается в интерфейсе. При отзыве токена требуется вручную заменить `WB_TOKEN`. HTTP 200 от WB не считается успехом без валидной истории.

## Откат и данные

На Worker можно вернуть предыдущую версию через Cloudflare Deployments. Отключение cron останавливает новые проверки; не удаляет историю и подписки. История ограничена 100 событиями. Чтобы удалить облачную историю, подписки и прочие данные, удалить Worker вместе с namespace Durable Object в Cloudflare; Google Таблица удаляется отдельно владельцем. Cloudflare может хранить резервные версии согласно своим срокам восстановления.
